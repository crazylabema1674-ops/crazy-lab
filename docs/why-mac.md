# 開発を進める上で Mac があった方が楽な理由（初心者向け）

> 対象：開発経験なし・副業の個人開発者が、Expo（React Native / TypeScript）で iOS / Android 両対応の「写真フォルダから子供の発達記録を作るアプリ」を、Claude Code などの AI に書かせながら作るケース。
> 作成日：2026年10月時点。価格・無料枠・要件は変わりやすいので、**数字はすべて目安**として扱い、最終判断の前に公式ページで確認してください。

---

## 1. 結論

- **Mac は「最初から必須」ではありません。** Expo には EAS（Expo Application Services）というクラウドサービスがあり、iOS アプリのビルド（アプリの完成品ファイルを作る作業）も App Store への提出も、Windows からクラウド経由で行えます。
- ただし **「iOS 版を安心してリリースし、育てていく」段階では、Mac があると圧倒的に楽** です。特に次のタイミングで「Mac が欲しい」と感じる可能性が高いです。
  1. **iPhone での動作確認の回数が増えたとき**（ビルド待ちが毎回 数十分〜数時間かかるため）
  2. **iOS 特有のエラーや権限まわりの不具合を調べるとき**（Xcode が使えないと原因が見えにくい）
  3. **App Store 申請用のスクリーンショットを揃えるとき**
  4. **フェーズ3で端末内 ML（Core ML・ネイティブモジュール）を入れるとき** ← ここは事実上ほぼ必須
- おすすめの考え方：**「フェーズ1は手持ちPC＋EASで始める → iOS 実機検証が増えた／申請前／フェーズ3着手前のどこかで中古の Apple Silicon Mac を導入」**。

## 2. Mac なし（Windows）で Expo でできること／できないこと

| 項目 | Windows でできる？ | 補足 |
|---|---|---|
| コードを書く（VS Code・Claude Code） | ◎ できる | 開発作業の大半は OS を問わない |
| Android エミュレータで動作確認 | ◎ できる | Android Studio を入れれば PC 上で Android 端末を再現できる |
| Android 実機で確認（Expo Go / 開発ビルド） | ◎ できる | USB または QR コードで簡単 |
| iPhone 実機で **Expo Go** を使って確認 | ○ できる | QR を読むだけ。ただし Expo Go に入っていないネイティブ機能は使えない。また App Store 版 Expo Go は最新の Expo SDK にしか対応しないことが多い |
| **iOS シミュレータ**（PC 上で iPhone を再現） | ✕ できない | Xcode 付属で **Mac 専用**。Windows では代替手段なし |
| **EAS Build** で iOS アプリをクラウドビルド | ○ できる | Apple の Mac サーバー上でビルドしてくれる。無料枠あり（後述）。待ち時間が長いことがある |
| 開発ビルド（Development Build）を iPhone 実機にインストール | ○ できる（手順が多い） | `eas device:create` で iPhone を登録 → 内部配布用にビルド → URL/QR からインストール。iPhone 側で「デベロッパモード」をオンにする必要あり |
| 署名・証明書の作成管理 | ○ できる | EAS が Apple アカウントにログインして自動作成・管理してくれる。トラブル時の手動対応は Mac の方が楽 |
| **EAS Submit** で App Store Connect / TestFlight へ提出 | ○ できる | Windows からコマンド 1 つで提出可能 |
| App Store Connect での申請情報入力・審査提出 | ◎ できる | ブラウザで操作するので OS 不問 |
| **Xcode** でネイティブエラーを調査・デバッグ | ✕ できない | Xcode は Mac 専用。Windows ではビルドログやクラッシュレポートを読む程度 |
| iPhone の詳細ログ（コンソール）をリアルタイムで見る | △ 難しい | Mac なら標準アプリ「コンソール」や Xcode で見られる |
| iOS のローカルビルド（`npx expo run:ios`、`eas build --local`） | ✕ できない | iOS のビルドには Mac＋Xcode が必須 |
| Swift でのネイティブモジュール開発・Core ML モデルの動作確認 | △ ほぼ無理 | コードは書けてもクラウドビルドでしか試せず、デバッグ手段がほぼない |

**ポイント**：Windows でも「作って、ビルドして、提出する」ことは一応一通りできます。できないのは **「iPhone 向けの確認・調査を手元で素早く回すこと」** です。

## 3. Mac があると楽になる具体的な場面

各項目に「Mac なしの場合の回避策」と「手間の大きさ」を併記しています。

### 3-1. iOS シミュレータでの動作確認
- **Mac があると**：コードを保存するとすぐ PC 上の仮想 iPhone に反映。iPhone SE のような小さい画面〜 Pro Max の大画面、iOS のバージョン違いも切り替えて確認できる。
- **Mac なしの回避策**：iPhone 実機＋Expo Go、または実機に開発ビルドを入れて確認。
- **手間**：中。手持ちの iPhone 1 台分の画面サイズ・iOS バージョンでしか確認できない。レイアウト崩れに気づきにくい。

### 3-2. 写真権限ダイアログや iOS 特有の挙動の検証
このアプリは「写真フォルダを読む」ことが中心なので特に重要です。
- iOS には「すべての写真へのアクセス」「選択した写真のみ（限定アクセス）」「許可しない」など複数の状態があり、それぞれで挙動が変わる。
- 一度許可・拒否すると、もう一度ダイアログを出すにはアプリ削除や設定変更が必要。
- **Mac があると**：シミュレータをリセットして何度でも初回状態から試せる。テスト用の写真をドラッグ＆ドロップで追加できる。
- **Mac なしの回避策**：実機でアプリ削除→再インストールを繰り返す。テスト用写真を実機の写真フォルダに入れる（家族写真と混ざる点に注意）。
- **手間**：中〜大。権限まわりは審査でも見られる部分なので、確認回数が多くなりがち。

### 3-3. Xcode でのネイティブエラー調査
- 起動直後にアプリが落ちる、ビルドが失敗する、といった問題は JavaScript 側ではなく **iOS ネイティブ側** で起きていることが多い。
- **Mac があると**：Xcode で詳しいエラー箇所・クラッシュログを見られ、それを Claude Code に渡して原因を絞り込める。
- **Mac なしの回避策**：EAS のビルドログを読む、Sentry などのクラッシュ収集サービスを入れる、TestFlight のクラッシュレポートを見る。
- **手間**：大。初心者にとって「原因の手がかりが少ない」状態は最もつらく、AI に聞いても情報不足で堂々巡りになりやすい。

### 3-4. ビルドの待ち時間・EAS 無料枠の制約回避
- EAS の無料プラン（2026年時点の目安）：**iOS・Android それぞれ月15回程度まで**、優先度の低いキューのため **混雑時は1時間以上待つ** こともある。1回のビルドは長すぎると打ち切られる制限もある。
- 開発ビルドは「ネイティブ部分を変えたとき」だけ作り直せばよいが、ライブラリ追加や設定変更のたびに必要になり、試行錯誤中は意外と回数を使う。
- **Mac があると**：`npx expo run:ios` や `eas build --local` で手元ビルドでき、待ち時間なし・回数無制限（数分〜十数分程度）。
- **Mac なしの回避策**：EAS 有料プラン（Starter など月額約19ドル〜）で優先キューにする。ビルド回数を節約するため、JS だけの変更は開発ビルドの再作成なしで確認する。
- **手間**：中。お金か時間のどちらかで払うことになる。

### 3-5. App Store 用スクリーンショット作成
- App Store には決められたサイズ（現在は主に 6.9インチ iPhone 用、iPad 対応ならiPad 用も）のスクリーンショットが必要。
- **Mac があると**：シミュレータで該当機種を選び、ダミーデータを表示した状態でスクリーンショットを撮るだけ。
- **Mac なしの回避策**：手持ちの iPhone で撮って画像編集ツール（Figma など）でサイズを合わせる、スクリーンショット作成用の Web サービスを使う。手持ち機種のサイズが要件と合わない場合は加工が必要。
- **手間**：中。子供の写真を扱うアプリなので、**実際の家族写真を写さないダミーデータ** を準備する手間はどちらにせよ必要。

### 3-6. 署名・証明書のトラブル
- iOS アプリは Apple の証明書・プロビジョニングプロファイルで「署名」しないと実機にもストアにも出せない。
- 普段は EAS が自動でやってくれるので Windows でも問題ないことが多い。
- **Mac があると**：トラブル時に Xcode やキーチェーンで状態を確認・作り直しでき、ネット上の解決記事（ほぼ Mac 前提）もそのまま使える。
- **Mac なしの回避策**：`eas credentials` コマンドと Apple Developer サイト（ブラウザ）で証明書を削除・再作成する。
- **手間**：小〜中（普段は小、トラブル時に中〜大）。

### 3-7. ネイティブモジュール／Core ML 追加時（フェーズ3）
- 顔判別・動作検出を端末内で行う場合、Swift（iOS）／Kotlin（Android）でネイティブモジュールを書き、Core ML モデルを組み込むことになる。
- **Mac があると**：Xcode で Swift コードの補完・エラー表示・ブレークポイントによるデバッグができ、Core ML モデルの中身確認や性能計測（Instruments）も可能。Create ML（Apple 純正の学習ツール）も Mac 専用。
- **Mac なしの回避策**：Swift コードを AI に書かせてクラウドビルド → 実機で試す、を繰り返す。クラウド Mac をレンタルする。
- **手間**：特大。1回の修正確認に数十分〜かかり、エラーの原因も見えにくい。**フェーズ3は Mac 前提で計画するのが現実的**。

### 3-8. TestFlight（ベータ配布）
- TestFlight は Apple 公式のテスト配布の仕組み。家族や知人に審査前のアプリを試してもらえる。
- **Windows でも**：EAS Build → EAS Submit → App Store Connect（ブラウザ）で TestFlight 配布まで可能。
- **Mac があると**：Xcode から直接アップロードしたり、TestFlight のクラッシュログを Xcode で詳しく見たりできる。
- **手間**：小。ここは Windows でもほぼ困らない。

### 3-9. 小まとめ

| 場面 | Mac なしの手間 |
|---|---|
| iOS シミュレータでの確認 | 中 |
| 写真権限・iOS 特有挙動の検証 | 中〜大 |
| Xcode でのネイティブエラー調査 | 大 |
| ビルド待ち時間・無料枠 | 中（お金で解決可） |
| App Store スクリーンショット | 中 |
| 署名・証明書トラブル | 小〜中 |
| ネイティブモジュール／Core ML | 特大 |
| TestFlight | 小 |

## 4. 開発フェーズ別の Mac の必要度

| フェーズ | Mac の必要度 | 理由 |
|---|---|---|
| **フェーズ1：MVP（AIなし・端末内完結）** | ★★☆☆☆（なくても進められる） | 画面作り・写真読み込み・記録保存は Android エミュレータ＋iPhone 実機（Expo Go／開発ビルド）で確認可能。ただし写真ライブラリまわりは Expo Go では制限があることもあり、早めに開発ビルドが必要になる可能性が高い。iOS 実機確認が増えると不便を感じ始める |
| **ストア申請（App Store 審査提出）** | ★★★☆☆（あると安心） | EAS Build／Submit で申請自体は可能。ただしスクリーンショット作成、複数画面サイズでの確認、審査リジェクト後の修正・再確認のサイクルで Mac の有無が効いてくる |
| **フェーズ3：端末内 ML 追加（顔判別・動作検出）** | ★★★★★（事実上必須） | Swift ネイティブコード・Core ML のデバッグ、性能測定は Xcode なしでは非常に困難 |

## 5. 費用の目安と選択肢（2026年時点の概算）

### 5-1. 前提知識：なぜ Apple Silicon（M1 以降）を推奨するか
- iOS アプリを App Store に出すには、**その時点で Apple が指定する新しめの Xcode でビルドする必要**がある（2026年4月以降は Xcode 26 以降が必須）。
- 新しい Xcode は新しい macOS を要求し、新しい macOS は古い Mac をサポート外にしていく。**Intel 製 Mac はまもなく macOS のサポートが終わる見込み**なので、中古で安くても避けた方が無難。
- → **M1 以降の Apple Silicon 搭載 Mac** を選べば、数年は安心して使える可能性が高い。

### 5-2. 最低スペックの目安

| 項目 | 最低ライン | 推奨 | 理由 |
|---|---|---|---|
| チップ | M1 | M2 以降 | M1 でも Expo 開発には十分動く |
| メモリ | 8GB | **16GB** | Xcode＋シミュレータ＋エディタ＋ブラウザ＋Claude Code を同時に動かすと 8GB はかなり厳しい |
| ストレージ | 256GB | **512GB**（または 256GB＋外付けSSD） | Xcode とシミュレータだけで数十GB を使い、ビルドのキャッシュも溜まる。256GB だと定期的な掃除が必要 |

### 5-3. 選択肢と費用感

| 選択肢 | 費用の目安 | 向いている人 | 注意点 |
|---|---|---|---|
| **中古 Mac mini（M1／M2）** | 約5万〜9万円（メモリ・容量で変動） | **コスパ最優先。最有力候補** | モニター・キーボード・マウスが別途必要（Windows PC のものを流用可） |
| 新品 Mac mini（M4） | 約9万〜13万円 | 長く使いたい、中古が不安 | 16GB メモリが標準になり、開発用途として扱いやすい |
| **中古 MacBook Air（M1／M2）** | 約6万〜11万円 | カフェや外出先でも作業したい | 8GB モデルが多いので 16GB を探すと割高 |
| クラウド Mac レンタル（MacinCloud など） | 月数千円〜（約25〜50ドル/月程度〜）。AWS の Mac インスタンスは最低24時間単位の課金で個人には割高 | フェーズ3の一時期だけ使いたい、まず試したい | 画面転送のため操作がもっさり。iPhone 実機を USB でつなげない場合が多く、シミュレータ中心の確認になる。長期的には中古 Mac の方が安くなりやすい |
| EAS 有料プラン（Starter） | 月額約19ドル〜（ビルドクレジット付き。iOS ビルド1回あたり数ドル相当） | 当面 Mac を買わずにビルド待ちだけ減らしたい | シミュレータや Xcode デバッグの問題は解決しない |
| EAS 無料プラン | 0円（iOS／Android それぞれ月15回程度まで、低優先キュー） | まずはここから | 混雑時は1時間以上待つことも |

### 5-4. Mac の有無に関係なくかかる費用
- **Apple Developer Program**：年額 約1.3万円（99ドル相当、為替・改定で変動）。App Store 公開や TestFlight には必須。
- **Google Play デベロッパー登録**：初回のみ 25ドル程度。
- **iPhone 実機**：後述（7章）。

> 価格は為替・在庫・時期で大きく変わります。中古は「Apple Silicon」「メモリ16GB」「バッテリー状態（MacBook の場合）」を確認して比較してください。

## 6. 推奨プラン

### ステップ1：手持ち PC（Windows でも可）＋EAS 無料枠で開始（フェーズ1前半）
- Android エミュレータ・Android 実機・iPhone 実機（Expo Go）で画面と基本機能を作る。
- 写真読み込みなどで Expo Go の限界が来たら、EAS で開発ビルドを作って実機に入れる。
- この段階では **Mac を買わずに「自分が本当に作り続けられるか」を確かめる** のが目的。

### ステップ2：iOS 実機検証が増えてきたら中古 Mac を導入（フェーズ1後半〜申請前）
- 目安となるサイン：
  - EAS のビルド待ちで1日の作業時間の多くが消える
  - 月の無料ビルド回数を使い切りそう
  - iOS だけで起きる不具合の原因がわからず、何日も止まった
- **中古 Mac mini（M1/M2、メモリ16GB、256〜512GB）** が費用対効果のバランスが良い。
- 迷ったら「EAS 有料プランを数ヶ月払う額」と「中古 Mac の価格」を比べる。数ヶ月〜1年以上続けるなら Mac の方が得になりやすい。

### ステップ3：ストア申請
- Mac があればシミュレータでスクリーンショット作成・複数サイズ確認。
- 提出自体は EAS Submit（Windows でも Mac でも可）を使うと簡単。

### ステップ4：フェーズ3（端末内 ML）着手前には必ず Mac を用意
- ここまで Mac なしで来た場合も、この段階で導入するか、最低でもクラウド Mac を契約する。
- Core ML のデバッグや性能確認は Xcode なしでは非常に効率が悪いため。

> **補足**：まだ PC 自体を買う段階なら、最初から Mac（M1以降・16GB）を選べば Android／iOS 両方の開発が1台で完結します。Mac では Android エミュレータも動きます。

## 7. iPhone 実機・Android 実機も必要か

### iPhone 実機：**ほぼ必須**
- シミュレータでは確認しきれないものがある：
  - 実際の写真ライブラリ（数千〜数万枚）を読むときの速度・メモリ使用量
  - カメラ、通知、バックグラウンド動作などの実際の挙動
  - フェーズ3の ML 処理速度（Neural Engine を使うかどうかで大きく変わる）
  - 手で持ったときの操作感
- Mac がない場合は **iPhone 実機が唯一の iOS 確認手段** になるので、なおさら必要。
- 目安：iOS の最新版に対応した機種。古すぎると最新 iOS が入らず、新しすぎると古い機種での動作確認ができない。フェーズ3を考えると、**ある程度新しい機種**（ML処理の速度確認のため）を推奨。中古でも可。

### Android 実機：**強く推奨（最低1台）**
- Android エミュレータは PC 上で動くので Windows でも Mac でも使えるが、写真の読み込み権限や性能はメーカー・機種によって差が大きい。
- Android は機種が多様なので、実機1台＋エミュレータで複数の画面サイズを確認するのが現実的。
- 中古の安価な端末（数千円〜2万円程度）でも十分役に立つ。ML 処理の速度確認用に、ミドルクラス程度の端末があると安心。

### 実機テストの注意点（このアプリ特有）
- 子供の写真を扱うので、**テスト用のダミー写真セット** を用意し、開発用端末と私物の写真が混ざらないようにするのがおすすめ（開発専用の中古端末があると安心）。

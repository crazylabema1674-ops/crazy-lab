## 1. サービス概要

| 項目 | 内容 |
|---|---|
| 一言で | スマホの写真フォルダから、子供の発達記録（いつハイハイ／つかまり立ち／ひとり歩きしたか等）を後から振り返って作れるアプリ |
| ターゲット | 5歳以下の子供を持つ子育て世代のパパママ |
| 解決したい悩み | 子育てに追われて発達記録をつけられず、1歳半健診・3歳児健診の問診票を書くときに必死に思い出し、曖昧になる |
| 着眼点 | 記録はつけられなくても、子供の写真はよく撮っている |
| 対象OS | iOS と Android の両方（悩みの性質上、両方が必須とユーザーが判断） |
| 開発体制 | 個人開発。開発経験なし。Claude Code 等のAIに書かせながら作る |
| 目的 | 副業としての収益化 |
| 想定価格 | 買い切り 500円前後 |

## 2. 議論で合意・整理した方針

### 価値の打ち出し方
- 差別化: 既存アプリ（ぴよログ、母子手帳アプリ）は「毎日記録する」前提。本アプリは **「記録してこなかった人でも、後からでも間に合う」**。
- 写真から分かるのは「初めてできた日」ではなく **「遅くともこの日にはできていた」日**。画面の言葉もそれに合わせる（例: 「◯◯している一番古い写真」）。
- 静止画だけでは区別しにくい動作がある（つかまり立ちと一人立ちなど）。乳幼児の姿勢推定はAIでも精度が低い。→ 完全自動ではなく **「候補を絞って並べる → 親が見て確定する」半自動** が基本。動画は判定材料として重要。
- 写真で答えられるのは主に体の大きな動き（粗大運動）の項目。言葉・指差し・指示理解などは写真では分からない。→ 健診の問診項目に沿ったチェックリストを用意し、写真で埋まらない項目は手入力。最終成果物は **「健診前にこれ1枚見ればいい」まとめ画面（PDF出力）**。
- **医療的な判定はしない**（「遅れています」等の表示や平均との比較はしない）。記録整理ツールに徹する（医療機器プログラム規制や不安をあおることの回避）。

### プライバシー・技術
- 子供の写真はサーバーに送らず、**端末内ですべて処理**する。これを安心材料として打ち出す。サーバー代が不要なので買い切りと相性が良い。
- 開発技術は **Expo（React Native / TypeScript）** を推奨。1つのコードでiOS/Android両方、AIに書かせやすい、Macなしでもクラウド（EAS）でiOSビルド可能。
- 顔認識（どの子の写真か）は iOS「写真」アプリの人物情報が他アプリから使えないため自前実装が必要 → フェーズ3まで後回し。

### 収益・費用
- Apple Developer Program 年 約12,800円、Google Play 初回のみ 25ドル。
- 手数料15%（小規模事業者向け）を引くと500円で手取り約425円。年 約35本でストア費用を回収できる。
- 単価が低く広告集客は赤字になりやすい → SNSの口コミ、健診時期の検索流入が中心。
- 案: **写真の読み込み・整理までは無料、健診まとめ（PDF出力など）を有料**。

### 競合
- みてね（家族アルバム。写真がみてねにしか無い家庭もある）、ぴよログ（毎日記録型）、母子手帳アプリ。
- 「既存の写真から遡って作る」ことに絞ったアプリは少ない → ここが差別化の軸。

## 4. 各検討ドキュメントの結論

### フェーズ0 ヒアリングチェックリスト → `docs/phase0-interview-checklist.md`
- 仮説10個（記録が続かない、健診で困る、写真を見返している、写真が端末内にある、困るのは運動の項目、兄弟の写真の混在、既存アプリへの不満、支払意思、プライバシー感覚、写真を見返せておらず「好き」の振り返りに価値がある〔H10・追加機能の検証用〕）に、成立／不成立の判断基準つき。
- 質問は約30〜35分（D9〜D11「写真の見返し方・好きの把握・習い事の選び方」を追加）。健診パートが最重要。問診項目の一覧（写真で分かるか○△×つき）を相手に見せて、困った項目を指してもらう。
- Mom Test の原則: 「欲しいですか？」ではなく過去の行動を聞く。アイデアは最後の3分まで言わない。
- Go の目安例: 「健診で困った具体的な話をした人が半数以上」「写真が端末にある人が7割以上」。
- 最後にAndroidテスター（12人×14日間のクローズドテスト要件）やSNSフォロー、自治体の問診票の実物を見せてもらうことをお願いする。

### フェーズ1 ユーザーフロー（兄弟対応含む） → `docs/phase1-user-flow.md`
- 推奨案: **写真は子供に割り当てず、記録（マイルストーン）だけを子供に割り当てる。**
  - 表示は子供タブで切替。同じ写真を選んだ子の月齢で並べ直す。見出しに「2歳3ヶ月（下の子 1ヶ月）」と兄弟の当時の月齢も併記。
  - 主な使い方は「ハイハイを探す」のようなマイルストーン起点。その子の月齢で起こりやすい期間の写真だけを、動画優先で表示。
  - タグ付け時にどの子の記録か確認（表示中の子が初期値、変更・複数選択可）。
- 年子: 子供ごとの色を大きく表示、保存後に「〇〇ちゃん（当時◯ヶ月）に記録しました」と出し、後から付け替え可能。
- 双子: 同じ誕生日を登録すると「双子モード」。タグ付けで毎回必ず子供を選択、2人の記録を並べて比較表示。早産なら修正月齢も。
- 写真への人物の手動割当は数万枚では非現実的 → フェーズ3のAI用にデータの置き場所だけ用意。
- 大量写真対策（AIなしで可能）: 1日1枚に間引く、スクショ除外、動画のみ、マイルストーン起点の期間絞り込み。
- タグ付けした写真は小さいサムネイルをアプリ内に保存（元写真が消えても記録が残る）。権限が一部許可・拒否の場合の挙動も整理済み。
- 7ペルソナ、16画面の一覧とASCIIワイヤーフレーム、未決事項10件を収録。

### Macがあった方が楽な理由 → `docs/why-mac.md`
- 最初からMacは不要。Expo の EAS を使えば Windows からでも iOS ビルド、App Store 提出、TestFlight 配布まで可能。
- Macなしで最も困るのは、iOS側のエラー調査と、フェーズ3の Core ML・ネイティブモジュール追加。写真権限まわりの検証も負担。
- 必要度: MVP ★2（なくても進められる）／ストア申請 ★3（あると安心）／フェーズ3 ★5（事実上必須）。
- 買うなら中古 Mac mini（M1/M2、メモリ16GB推奨）で約5万〜9万円。Intel Mac は避ける。
- iPhone実機はほぼ必須、Android実機も最低1台推奨。テストは家族写真ではなくダミー写真・開発専用端末で。

## 5. 優先して確かめるべきリスク

1. **Androidで、Googleフォトのクラウドにしかない写真を読めるか**（読めない家庭が多いと前提が崩れる）。iOSもiCloud「ストレージを最適化」だと原本はクラウド（撮影日とサムネイルは取得可）。
2. **Google Play の写真全件アクセス権限の審査**（中心機能として申告が必要）。
3. **健診で本当に困るのは体の動きの項目か**（言葉の項目が中心なら写真の価値が下がる）。
4. **夫婦で別々のスマホに写真がある家庭**（サーバーなしでは同期できない。未決）。

## 9. 検討中のアイデア: 個性・「好き」の発見（2026-11-09 議論）

### 背景（ユーザーの実感）
- 子供2人の写真を大量に撮っているが、見返せていない。スマホには財産がたくさんあるのに活用できていない。
- 発達記録の抽出は、その「活用」の1つという位置づけ。→ 「撮りっぱなしの写真を、意味のある記録に変える」がより大きなコンセプトになりうる。

### 「才能を見つける」機能への見解（現時点の整理）
- 良い点: 楽しく、SNSで共有したくなる（口コミ集客と相性が良い）。健診のような時期限定でなく、何歳でも使える。
- 注意点:
  - 写真に写るのは「親が撮りたいと思った場面」や「親が連れて行った場所」。子供の才能ではなく親の関心が反映されやすい。
  - 「運動の才能あり」等の断定は根拠を示せず、誇大表示や、子供へのレッテル貼り・兄弟比較の不安につながる。「医療的な判定はしない」方針とも同じ考え方で、**能力の判定はしない**。
  - 「何をしている写真か」の自動判別は端末内AIが必要で、フェーズ3相当の難しさ。
- 方向性の案: 「才能判定」ではなく **「夢中・好きの記録」**（例: 2歳は電車、3歳は虫の写真が多い、を年表やカードで振り返る）。言葉は「才能」ではなく「好きだったもの」「夢中だったもの」。
- 優先順位: MVPは健診まとめ（困りごと＝お金を払う理由）に集中。「好きの記録」は無料の楽しい機能・拡散用として、フェーズ2〜3の追加候補。ヒアリングで健診の困りごとが弱ければ、こちらを主軸にする選択肢もある。
- ヒアリングへの反映（済）: 仮説H10と質問D9〜D11（写真を見返す時・見返さない理由、子供の「好き・得意」の把握方法、習い事を選んだときの参考）を `docs/phase0-interview-checklist.md` に追加。記録テンプレート・集計表・「修正」の判断表（健診は弱いがH10が強い場合 →「好きの記録」主軸を検討）にも反映。

## 10. 机上調査: 「写真を見返せない・活用できていない」課題 → `docs/research-photo-underuse.md`（2026-11-09）
- 課題があることはほぼ確か（国内: 子育て世帯の約9割が写真整理に不満、整理しない理由1位は「面倒」。海外: スマホ写真の約70%は二度と見返されない）。ただし調査の多くはフォトブック会社によるもので、数字は目安。
- ただし「気にはなるが困ってはいない」弱い悩みの可能性が高い。一般的な振り返りは、スマホ標準の「思い出」機能（無料）、みてね（国内パパママの約65%が利用）、プリント定期便などで混み合っている。
- 結論: 「見返せない」は共感を得る入口として使い、買う理由は「健診で困る」のような具体的な場面に置く。現在の健診まとめの方針を後押しする結果。
- ヒアリングで追加確認: 見返せないことに対して実際に行動・支払いをしたか（フォトブック、定期便、代行など）、標準の思い出機能やみてねで満足しているか。

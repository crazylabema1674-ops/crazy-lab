## 調査結果の要約（2026-11-22）

詳細: `docs/harmony-research-competitors.md`（競合・需要）、`docs/harmony-research-technical.md`（技術・費用）、`docs/harmony-research-theory.md`（ハモリの理論とAIの仕組み）

- **技術そのものは既にある**: Kits.ai、Wondera、Audimee など海外のWebサービスが「歌の録音 → 歌詞つきハモリを別のAIの声で」を提供。MITの研究も同じ仕組み。
- **ただし空白はある**: 気軽に歌う人向けのスマホアプリ／アカペラ1曲まるごと／キー自動判定／声で直しを頼める／日本語・J-POP前提／SNS投稿まで一つの流れ、を満たすものは見つからなかった。差別化は技術ではなく「体験の作り込み」。大手のスマホ参入で追いつかれるリスクあり。
- **需要は「根強いが小さめ」**: カラオケ人口は約4,000万人だが、ハモリ動画は数千〜数万回再生程度。支払意思は要検証。
- **作れるか**: 全部は★4（2回目の歌にテンポを合わせる部分は★5・研究レベル）。「1回目の歌＋AIハモリの二重唱を聴く」小さい版なら★3で、オープンソース部品（RMVPE、RVC）で現実的。
- **お金**: 必要な時だけ動くGPUサーバー＋RVCなら1曲約1〜14円【推定】で、月300円は回数上限つきなら成立。外部API（約54円/曲）は赤字。
- **最大の壁は権利**: 変換先の歌手の書面同意（3段階）、J-POPの著作権（特に共有機能・歌詞表示）、モデルのライセンス。SNSはYouTube・TikTok・Instagramが中心（Xは許諾なし）。
- **次の一手（推奨）**: ①Kits.ai・Wondera に自分のアカペラを入れて「楽しいか」を確かめる。②プログラムなしの手作業デモ（録音→音程を上げる→RVCで声変換→重ねる）を友人に聴いてもらう。
- **試用の確認項目**: `docs/harmony-trial-checklist.md`（Wondera を試す予定。**未実施**。ユーザーがタイミングを見て試す。試したら結果を聞き取って記入する）

## 1. アイデアの原点

- ユーザー本人は、洗い物中・通勤の車内・お風呂などで、曲をかけずによく歌っている。
- 新しい楽しみとしてハモリに挑戦したが、やり方が分からず断念した。
- YouTubeで「サビのハモリだけを歌っているチャンネル」を見つけ、それに重ねて歌うと **1人で歌うよりずっとうまく聞こえて楽しかった**。
- → 「誰々の〇〇を一緒に歌おう！」と声で頼むと、ハモリを歌ってくれるアプリがあれば素敵。

## 2. ヒアリングで分かったこと（本人）

| 質問 | 回答 | 示唆 |
|---|---|---|
| 伴奏は必要？ | YouTubeでは伴奏なしのものも、ピアノ・ギター弾き語りのものもあった | 伴奏は必須ではない |
| テンポは？ | 普段は好きなテンポだが、原曲のテンポはある程度意識している | 原曲のテンポで流れるハモリに合わせるのも受け入れられそう |
| ハモリの声は？ | YouTubeで体験したのは「上手な別の歌手の声」 | 自分の声を機械で上下にずらすだけでは、同じ感動にならない可能性 |

| YouTubeの不満は？ | **サビしかない、歌いたい曲がない** が最大の不満 | アプリの価値は「どんな曲でも」「1曲まるごと」 |

| 他に使う人は？ | 周りは分からない。暇なときに何となく歌う人は多いと思う | 需要は未確認。要検証 |

| ハモリに歌詞は必要？ | **歌詞がないと楽しくない** | ユーザーの録音をもとに声を変換する方式（歌詞が残る）が必須 |
| お金の取り方 | 基本無料（1回30秒程度・月の回数制限あり）／月300円で1回3分まで／月500円で回数無制限 | サーバー代との釣り合いを要計算 |

### 本人の理想像
ハモリに特化したAIに「〇〇を歌おう」と言うと、うまくハモリパートを作ってくれる。歌いながら「もっと高く」などとお願いすると調整してくれる。

## 3. 作り方の候補

| | 案1: 曲ごとのハモリ音源を流す | 案2: 声を聞いて自動でハモる | 案3: 曲名からAIがハモリを作る |
|---|---|---|---|
| 体験の近さ（本人のYouTube体験） | ◎ | △（自分の声っぽくなる） | ○ |
| 歌える曲 | 用意した曲だけ | どんな曲でも | 多い |
| 著作権 | ⚠ 許諾が必要な可能性が高い | ○ 曲データを持たない | ⚠ |
| 個人開発での難しさ | 中（音源づくりが大変） | 中〜高 | 非常に高い |

## 4. 現時点で見えている論点・リスク

1. **著作権（最重要）**: 既存曲のハモリを作って配信すること自体が、曲の「編曲」にあたる可能性がある。YouTubeの「歌ってみた」はYouTubeと著作権団体の包括契約で成り立っているが、自前のアプリでは同じ仕組みが使えない可能性が高い。→ 専門家・公式情報で要確認（未確認）。
2. **YouTubeとの違い**: すでにYouTubeで体験できている。アプリにする理由（お金を払う理由）は何か。
3. **声で操作する場面の音響**: お風呂・車内でスピーカーから音を出すと、マイクがアプリ自身の音も拾ってしまう。
4. **「別の歌手の声」をリアルタイムで作るのは難しい**: 声をその場で別人の声に変えると、遅れ（ズレ）が出やすい。

## 5. 新しい有力案: 「1回歌うと、AIがハモリを返してくれる」型

AIは流行りの曲のメロディを正確には覚えていない。原曲の音源をアプリで分析することも、配信サービス（Spotify等）の規約上ほぼできない。
→ **メロディの情報源を「ユーザー自身の歌声」にする**。

1. ユーザーが「〇〇を歌うね」と言って、1曲（または1コーラス）歌う
2. AIが歌声から音程とリズムを読み取り、曲の調（キー）を推定してハモリの音を決める
3. ユーザーの録音の音程をハモリの音に移し、声質を「別の上手な歌手の声」に変換して返す（歌詞もテンポもユーザーの歌がもとなので自然に合う）
4. 2回目からはそれに重ねて歌う。「サビはもっと高く」などと声で頼むと作り直す

- 良い点: どんな曲でも1曲まるごと対応。アプリが曲のデータを持たない。本人の「好きなテンポ」にも合う。
- 課題:
  - 技術的に難しい（声質の変換は端末内では重く、サーバーで処理する可能性大 → サーバー代がかかり、買い切りより月額向き）
  - 「別の歌手の声」のもとになる声の権利（声の提供者の許可が必要）
  - 著作権: アプリが曲を配信しないので案1より有利と思われるが、未確認。専門家への確認が必要
  - 最初の1回はハモリなしで歌う必要がある（すぐ一緒に歌えるわけではない）

## 7. 宣伝のアイデア

- AIとハモった動画をSNSに投稿 → 「どうやってるの？」で興味を持ってもらう。
- アプリに「ハモった音声を動画にして共有」機能を入れると、使った人が自然に宣伝してくれる。
- 注意: SNSによって、既存曲を歌った動画を投稿してよいかの扱いが違う（著作権団体と契約しているかどうか）。投稿先ごとに要確認。
- 本格的に作る前に、手作業で作ったデモ動画を投稿して反応を見る、という需要の確かめ方もありうる。

## 8. 方向性の候補（検討中・旧）

- A. **ハモリ再生型**: 曲ごとのハモリ音源に合わせて歌う（案1）。体験は一番近いが、著作権と音源づくりが課題。
- B. **ハモリ練習型**: ハモリの歌い方を教える。本人の「ハモれるようになりたい」に応える。
- C. **A＋Bの組み合わせ**: 最初は重ねて楽しむ → 慣れたら自分でハモる側に回る。
